# 台股強勢股掃描

每日盤後自動掃描全市場(上市+上櫃普通股),產生兩份清單:

- **SEPA Trend Template** — Minervini 七條件 + RS Rating(相對大盤超額報酬,全市場百分位 1–99)
- **當日強勢** — 漲幅 ≥ 4%、量比 ≥ 1.5、成交值 ≥ 1 億

同時每日重建台指選擇權(TXO)的 **Gamma 結構**：不推測 Dealer 方向的 Gamma Concentration，以及保留原假設的 Signed GEX；座標為期貨遠期價。

> ⚠️ **先讀這個**:GEX 位階經過 278 個交易日的實測,**對交易決策幫助有限** —— 牆的彈回率與隨機位階無異、flip 當觸發點沒有方向性、唯一顯著的波動訊號已被隱含波動率定價完。詳見〈[實測結果](#-實測結果這些位階對交易決策幫助有限)〉。有價值的是「gamma/OI 集中在哪裡」這個事實陳述本身。

架構:GitHub Actions 每個交易日 15:30(台北)自動抓資料、計算、commit 結果 → GitHub Pages 提供靜態前端。零伺服器、零費用。

## 部署步驟

1. 把這個資料夾推上 GitHub(public 或 private repo 皆可,Pages 需 public 或付費方案)
2. **回補歷史資料**(只需做一次):
   - 本機執行:
     ```bash
     pip install pandas requests numpy scipy
     python scripts/update_data.py --backfill
     python scripts/txo_gex.py --backfill
     ```
   - 個股/大盤呼叫證交所、櫃買中心免費歷史 API,約 280 個交易日跑數分鐘;GEX 呼叫期交所選擇權下載,按月切片,通常一兩分鐘內完成。皆無需金鑰、無需註冊
   - commit 產生的 `data/history.csv.gz`、`data/gex_history.csv`、`docs/data/latest.json`、`docs/data/gex_latest.json` 並 push
3. Repo → Settings → Pages → Source 選 `Deploy from a branch`,分支 `main`、目錄 `/docs`
4. Repo → Settings → Actions → General → Workflow permissions 選 **Read and write**
5. 完成。之後每個交易日 15:30 會自動更新,也可到 Actions 頁面手動觸發

## 篩選邏輯

**SEPA(七條件全過 + RS ≥ 70):**
1. 收盤 > 150MA 且 > 200MA
2. 150MA > 200MA
3. 200MA 上升(對比一個月前)
4. 50MA > 150MA > 200MA
5. 收盤 > 50MA
6. 收盤高於 52 週低點至少 30%
7. 收盤距 52 週高點 25% 以內

RS Rating 採 IBD 式加權:40% 三個月 + 各 20% 六/九/十二個月的**超額報酬**(個股報酬 − 加權股價指數同期報酬),全市場排百分位。上市、上櫃股票統一以加權指數(大盤)為基準,而非各自比較所屬市場的指數。

**當日強勢:** 漲幅 ≥ 4%、量比(當日量/20 日均量)≥ 1.5、成交值 ≥ 1 億。

**動能篩選 + 市場廣度:**

1. 收盤 > 200MA
2. 10MA > 20MA
3. 總市值 ≥ 20 億
4. 成交值 ≥ 5,000 萬
5. 近 20 個交易日漲幅 − 同期加權指數漲幅 > 10 個百分點

每日通過的**檔數**就是市場廣度 —— 同樣是大盤上漲,通過的檔數在擴張還是萎縮,代表漲勢是全面的還是集中在少數股。

#### 2026-09-18:第 5 條從絕對漲幅改成相對大盤

原本是 TradingView 那組的「一個月漲幅 ≥ 20%」。絕對門檻的問題是它**跟著大盤走**,廣度因此混進了大量「大盤本身漲多少」的成分:

| 日期 | 大盤 20 日漲幅 | 舊(21 日漲幅 > 20%) | 新(20 日超額 > 10) |
|---|---|---|---|
| 2026-05-04 | +22.7% | 290 | 172 |
| 2026-03-31 | −7.6% | 54 | 169 |
| 2026-07-31 | −7.7% | **8** | 60 |

大盤一個月漲 23% 時,舊條件把跟著大盤水漲船高的都算進去;大盤跌 8% 時,舊條件幾乎歸零,看不出誰在逆勢撐住。新條件選的是「跑贏市場」,不是「剛好在漲的市場裡」。大方向一致,但極端行情時差到 100 檔以上。(視窗從 21 日改成 20 日本身影響很小:兩個版本的超額條件在 280 天裡相關係數 0.98。)

實作上兩件事要注意:

* **大盤漲幅用這檔股票自己的視窗算**(它 20 根 K 棒前那天到今天)。中間停牌過的個股,這個起點會早於「全市場 20 個交易日前」,要比就得比同一段。
* **「一個月」是 20 個交易日**(四週)。原本用 21(= 252/12,與 RS 的 63/126/189/252 同一套換算),同一天改成 20。兩者都只是近似 —— TradingView 的「1 個月」是日曆月,實際落在 20~23 個交易日之間。
* **改任何篩選參數之後**跑 `python scripts/update_data.py --rebuild-breadth`:用目前條件整段重算廣度與上榜名單(有 `history_long.csv.gz` 可重算滿 280 天)、保留題材標籤、更新回測快取,再重產 `latest.json`。美股是 `python scripts/us_breadth.py --backfill`。
* **一個月績效可以是負的了**(大盤跌 20% 時跌 5% 的股票超額 +15 會過),前端原本寫死的正號已拿掉。

`breadth.csv` 與 `momentum_members.csv.gz` 已用新條件**整段重算**,每一天都只用那天往前 280 個交易日的資料,跟線上流水線當天看得到的一樣 —— 否則切換當天會出現一個不存在的斷層(舊 96 → 新 122 看起來像廣度突然擴張)。回測與廣度研究的名單快取檔名帶著條件指紋(`SCREEN_SIG`),條件一改自動失效,**先前那兩份研究的結論是舊定義下的結果**。

改條件時順便發現 `data/index.csv.gz` 缺了 2026-07-21 起的 25 天(`git add` 漏列那段時間留下的),這個洞同時也在影響 **RS**(它用大盤 63/126/189/252 日報酬當基準),已從證交所補齊。

### 族群題材

`scripts/themes.py` 對每檔通過篩選的個股抓 Google News RSS 標題,用**關鍵字比對**判斷題材(CPO・光通訊、PCB・CCL、AI 伺服器散熱、航運、記憶體…),並標記**處置股/注意股**這類風險旗標。81 檔約 18 秒。

刻意不用 LLM —— 這支跑在排程裡,要保持免費且無外部相依。代價是:

- **新題材抓不到**:詞典裡沒有的詞就是沒有(關鍵字表在 `themes.py` 頂端,可直接增修)
- **無法判斷某則新聞是不是真的在講上漲原因**:市場總覽型的文章會列很多股票,可能誤導歸類
- 目前**未歸類約 28%**

所以**原始標題會一併輸出**,未歸類那組在前端會直接把標題攤開 —— 歸不了類時人可以自己判斷,也可以之後把這批標題餵給 LLM 做更好的分類。

#### 覆寫檔與 `-`

`data/theme_overrides.csv`(美股 `data/us_theme_overrides.csv`)由排程的研究任務維護,優先於關鍵字。`source` 欄固定寫「本文讀到的事實 | 本文: 網址」,可以回頭查核。

theme 填 **`-`** 代表「讀過本文、確定是個股因素或投機,不屬於任何族群」,跟沒寫是兩回事:

| | 網頁 | 研究任務 | 關鍵字判斷 |
|---|---|---|---|
| 填 `-` | 未歸類組裡標 ✓,不列入「待判斷」的標題清單 | 跳過(超過 30 天又回榜可重查) | 被蓋掉 |
| 沒寫 | 未歸類組,標題攤開等判斷 | 下次再查 | 照常 |

兩個用途:蓋掉關鍵字的誤判(關鍵字每天重算,不寫 `-` 明天又會歸回錯的題材),以及記住「查過了」,不必每天重查同一檔個股行情。讀不到本文的**不能**填 `-`。

族群日增減在計算前一天的分組時,`-` 一樣算數 —— 否則被蓋掉的個股前一天會退回歷史上那個錯的標籤,只要它還在榜上,網頁每天都會顯示「原題材 −1、未歸類 +1」。

計分方式是「有幾**則不同的新聞**提到該題材」而非關鍵字出現次數(否則一則塞滿同義詞的標題就能決定結果),且 Google News 每次回傳結果會變,所以取 12 則標題求穩定(只取 6 則時同一檔前後兩次會歸到不同題材)。

**美股版**(`scripts/us_breadth.py`)用同一組條件,門檻改為市值 ≥ $5 億、成交值 ≥ $500 萬,宇宙約 3,300 檔。第 5 條同樣在 2026-09-18 改成相對大盤,基準是 **S&P 500(`^GSPC`)**:一個月漲幅 − 同期 S&P 500 漲幅 > 10 個百分點。

要知道的副作用:這段期間 S&P 500 一個月漲幅多在 ±3% 以內,新門檻實際上約等於「漲超過 10%」,比舊的 20% 寬很多,通過檔數明顯變多(2026-06-30 舊 260 檔、新 760 檔)。這是「超額 > 10」在盤整市的自然結果,不是 bug;大盤單月大漲時則會反過來比舊條件嚴。

- 宇宙與市值:**Nasdaq screener**,一次回傳全美約 7,000 檔
- 每日 K 線:**Yahoo chart API**,逐檔但一次給一整年 —— 所以回補與每日更新成本相同(實測 3,346 檔約 80 秒),不必像台股那樣累積價格檔案

⚠️ Yahoo 那支是**非官方 API**,沒有服務保證,隨時可能改格式或擋人,性質與證交所官方資料完全不同。腳本會統計抓取失敗率,超過 25% 會警告。目前實測缺漏約 4%。每日更新抓一年;`--backfill` 抓兩年,扣掉 SMA200 的回看後可重算約 280 天的廣度與名單(改條件時就是這樣整段重算的),同一天同一檔原本標好的題材會保留。

**美股歷史宇宙可信度：**從本次修改起，排程會在美股收盤後 18 小時內，把 Nasdaq 當時市值 > $5 億的名單與市值按日保存到 `data/us_universe/YYYY-MM-DD.csv.gz`。歷史回補優先用對應交易日的快照；只有快照建立之後的日子，才能稱為「當時觀察到的宇宙」(`universe_basis=observed_snapshot`)。更早的 `--backfill` 仍只能用**今天的名單和市值**重建，會標 `reconstructed_current`；既有無來源標記的行標為 `unknown_legacy`。`coverage_pct` 記錄當次能從 Yahoo 取到圖表的名單比例，不能把缺漏誤認成沒有股票。不能把舊序列說成消除了生存者偏差。回補時也會嘗試抓快照中後來不在當前名單裡的股票；Yahoo 抓不到的下市股票仍是缺口。完整的歷史市值、下市報酬需要含股票身分沿革的資料庫，例如 [CRSP 的資料欄位](https://wrds-www.wharton.upenn.edu/demo/crsp/form/)。網站今日名單仍使用每日觀察，歷史可信度標記隨 `us_latest.json` 的廣度資料保留。

盤中執行時 Yahoo 會回一根還沒收完的「今天」,而每日更新遇到已經有廣度的日子會跳過 —— 盤中算出來的半根 K 棒會永久留在紀錄裡。排程都在美股收盤後跑所以沒踩過,但手動執行會,所以紐約時間 16:20 之前一律丟掉當天那根。

### 台股長期回測的價格品質

`scripts/backtest_momentum.py` 現在會讀取 `scripts/corporate_actions.py` 收集的[證交所除權息計算結果](https://www.twse.com.tw/zh/announcement/ex-right/twt49u.html)及[櫃買中心除權息計算結果](https://www.tpex.org.tw/zh-tw/announce/market/ex/cal.html)，用官方「除權息參考價／前一日收盤價」將事件之前的 OHLC 換算到同一價格尺度，供均線、20 日漲幅與持倉報酬使用。原始行情維持不變，市值仍用原始收盤價。這是**含權息報酬的近似**，不是逐筆現金股利、配股、認購權與稅費的精確結算。需要最新事件時加 `--refresh-actions`；快取的涵蓋日期記在 `data/corporate_actions_meta.json`，不足時腳本會自動補抓。

2023-01-03～2026-09-24 的歷史日線有 6,264 筆官方事件能直接對上；原始價有 534 次單日超過 10.5% 的跳價，校正後剩 241 次。剩下的可能是減資、面額變更或停牌恢復等，回測對含這類事件的 200 日技術視窗不產生訊號，持有時遇到則列為**無法評價的排除交易**。報告中的勝率與損益因此是可評價交易的結果，不能拿排除者當作零損益。歷史市值仍使用目前的發行股數；在增減資前可能失真。名單快取會綁定除權息資料的內容雜湊，避免把舊未校正名單當新結果。

校正後重跑 2023-11-06～2026-09-24（每次新上榜隔日投入 1 萬元、原價手續費且每筆最低 20 元）：7% 停損為 10,427 筆、損益 **-227,818 元**（另排除 9 筆）；10% 停損為 8,801 筆、損益 **+181,383 元**（另排除 13 筆）。這是重複投入的交易損益加總，沒有資金上限與部位大小約束，不等於帳戶報酬率；與舊報告相比同時改了事件校正、篩選名單及期末日期，不能把差額全歸因於除權息。可重跑 `python scripts/backtest_momentum.py --start 2023-11-06 --r 0.07,0.10 --out backtest_adjusted.txt`。

### 新上榜訊號的固定持有期間研究

[2026-09-24 截止的研究](reports/signal_entry_study_2026-09-24.md)拿掉停損停利，改成新上榜隔日開盤買、持有5／10／20交易日收盤賣，同股不重複持有。為公平比較，三組訊號均截止2026-08-27，並用官方加權指數的同日開盤到出場日收盤作基準。扣原價手續費與交易稅後，平均超額分別為 **-1.24／-1.29／-1.74個百分點**；不扣成本仍落後，逐年方向一致。改低成本、排除除權息期間或保留重疊訊號也未改變結論。這支持先檢驗「上榜隔天就買」的有效性，還不能推出哪種新進場規則會更好。

重跑：`python scripts/signal_entry_study.py --start 2023-11-06 --end 2026-09-24 --out _signal_entry_study.md`。大盤開高低收保存在 `data/taiex_ohlc.csv`，範圍記錄在 `data/taiex_ohlc_meta.json`；遇到不足月份會補抓。仍有歷史股數、股利口徑、交易成交與資料排除限制；報告列出稽核數量、每上榜日等權及40日區塊重抽結果，不能把每筆交易當成獨立樣本。

### 廣度跌破5／10／20日均線

[均線跌破研究](reports/breadth_ma_study_2026-09-24.md)用網站同一篩選口徑重建長期廣度，另外核對網站已存資料。跌破指前日≥均線、當日<均線，收盤確認後從次日開盤觀察5／10／20交易日。事件至少相隔20日，一般交易日按事件年度配重，並用40日區塊重抽處理相關性。

截至2026-09-24的資料未顯示穩定的轉弱效果；去重後每條均線只有22～27次。5／10MA在去重樣本的偏強結果，納入所有跌破後幾乎消失，不能據此當買進訊號。「每日低於20MA」的20日報酬略低於一般日，但觀察高度重疊，也尚不足以作可靠看空規則。重跑：`python scripts/breadth_ma_study.py --out _breadth_ma_study.md`。

### ATR 風險距離比較

`python scripts/backtest_atr.py --start 2023-11-06 --end 2026-09-24 --fixed 0.07,0.10,0.12 --atr 1.5,2,3 --out _atr_study.md` 可比較固定停損和 14 日 Wilder ATR。ATR 只取上榜日已知值，進場後固定 1R 距離；沿用原有保本和整數 R 階梯，並非每日重設 ATR 追蹤停損。每檔仍投入一萬元，沒有改成每筆等風險部位。

[2026-09-24 截止的完整結果](reports/atr_study_2026-09-24.md)：原價手續費下，1.5／2／3 倍 ATR 的淨損益分別為 -421,331／-74,943／+694,085 元。3 倍 ATR 的初始停損中位數為 12.04%，所以另外加入固定 12% 對照（+459,066 元）。3 倍 ATR 的獲利主要集中於 2026，2024、2025 仍虧損；這是同一歷史樣本的探索，尚未證明穩定優於固定停損。各方案持倉時間、交易筆數與承擔風險不同，損益加總不等於帳戶報酬率。

總市值需要發行股數,上市取證交所公司基本資料 OpenAPI(`t187ap03_L`),上櫃直接在每日行情的「發行股數」欄位裡就有。**兩個來源都只給當下股數、沒有歷史**,所以回補歷史廣度等於用今天的股數乘過去的股價,遇到增減資的個股會失真;市值門檻只是粗篩,影響有限但要知道。SMA200 需要 200 天歷史,所以 280 天的視窗只能回補最近約 80 天的廣度,之後會隨資料累積變長。

兩份清單都要求成交值 ≥ 1 億。少了這道濾網,SEPA 會有三成是一天只成交幾十萬元的個股 —— 技術面條件再漂亮也建不了倉。

門檻都是 `scripts/update_data.py` 頂端的具名常數(`MIN_VALUE`、`MIN_RS`、`DAILY_CHG`、`DAILY_VOL_RATIO`),可自行調整。

## GEX 位階

用 TXO(台指選擇權)每日結算價,透過買賣權平價反推該選擇權到期日的隱含遠期價(不必另抓加權指數估股利率),Black-76 反推 IV。這個 `F` 與網站顯示的台指期主力月可能**不同到期**，不能把原始履約價直接當作台指期點位。輸出分成兩套模型，不能混用:

### Gamma Concentration（不推測 Dealer 方向）

- 原本的 `peak`（山頂）與 `valley`（山谷）仍保留在此區，沿用舊 `gross = (CallOI + PutOI) × Gamma` 和共用 IV 的算法；`concentration_peak`、`concentration_valley` 則是新模型結果，兩者可能不同
- `gamma_concentration_by_strike()` 分開計算 `CallOI × |CallGamma|` 與 `PutOI × |PutGamma|`
- `total_gamma_concentration = Call concentration - Put concentration`，表示兩邊相對集中程度，不代表 Dealer 正負 Gamma
- `cluster_concentration = Call concentration + Put concentration`，用來找最強 clustering strike
- **Concentration Peak** 是 `|Call-Put|` 最大處；**Concentration Valley** 是 Call+Put 總量的局部低點
- **Call / Put Concentration Peak** 分別顯示兩邊最集中的履約價

最新逐履約價明細寫在 `docs/data/gex_debug.json`。也可執行
`python scripts/txo_gex.py --debug YYYY-MM-DD`，欄位包含 strike、Call/Put OI、
Call/Put gamma、兩邊 concentration、淨 concentration 與舊 signed GEX。

### Signed GEX（依賴 Dealer positioning assumption）

原模型完整保留，仍以 Dealer long Call / short Put 為假設，產生:

- **Call Wall / Put Wall** — 現價上/下方 net gamma 最大的履約價
- **Micro Flip** — 總 GEX 由負轉正/正轉負的價位(全部到期日)
- **Macro Zero** — 同上,但只用到期日 > 7 天的合約

`gex_curve()`、`gex_at()`、`gex_by_strike()`、`regime_label()` 與 Call/Put Wall、
Micro Flip、Macro Zero、regime 都依賴這個方向假設。Gamma Peak 不等於 Gamma Flip；
程式不會把突破 Concentration Peak 解讀成正負 Gamma 切換。

Concentration Valley 找**Call+Put concentration 的局部低點**,不是區間最小值 —— gamma 隨著遠離價平單調衰減,取全域最小會永遠落在掃描窗最外緣那根空履約價上。實作先把履約價分箱(近月有 50 點檔,量能遠小於百點檔,不分箱會每根都被誤判成谷),再用 prominence 篩深度。找不到夠深的谷就回空值,不硬給數字。這只表示集中度較低，不自動解讀為跌破後加速。

`regime` 為正代表造市商避險行為傾向壓抑價格波動,為負則傾向放大波動。多空 gamma 幾乎抵銷時會標 **neutral** —— 判斷依據是 `net_ratio`(淨 gamma / 總 gamma),低於 `NEUTRAL_RATIO` 就不給正負。這個門檻有實測依據:`net_ratio` ≤ 0.05 的日子,正負號隔日翻面率是 63~65%(比擲銅板還糟),跨過 0.05 掉到 36%,超過 0.2 只剩 12.5%。

結算日當天到期的合約整批排除:期交所對最後交易日的到期序列不發結算價(整批寫 0),反推不出 IV,且收盤後那份 gamma 不再產生盤中避險。

**盤前快照**:排程跑在台北早上 07:00,此時當日夜盤(前日 15:00~當日 05:00)已收、日盤尚未開,期交所已發布夜盤收盤價但還沒有當日 OI。這時先用前一收盤日已知的 `台指期結算價 - 選擇權 F`，把夜盤台指期價格扣回選擇權座標，再重算 `gex_now` / `net_ratio` / `regime`,輸出成 `preopen_*` 欄位。位階仍沿用上一交易日的 OI 與 IV；盤前欄位不寫進歷史檔，因為它是暫時狀態。夜盤基差可能變動，這只是以上次已知價差估算。

前端以**價格階梯**呈現:原始 GEX 履約價與 Flip 仍保存在 `data/gex_history.csv` / `docs/data/gex_latest.json`，網站顯示時才加上同日已知的 `台指期結算價 - 選擇權 F`，換成台指期**估算**點位，再與台指期實際結算或夜盤價計算距離。每列仍標示原始履約價，頁面下方顯示所用日期與基差。台指期價格取自期交所 `futDataDown`(商品代碼 `TX`),選 **OI 最大**的月份而非最近月。換月、不同到期與夜盤基差變化都會產生估算誤差；這不是逐筆同步報價。

品質過濾門檻(`MIN_OI`、`MIN_PRICE`、`VALLEY_MIN_DEPTH`、`NEUTRAL_RATIO`)會顯著影響結果,都在 `scripts/txo_gex.py` 頂端可調整。

### 📉 實測結果:這些位階對交易決策幫助有限

**2026-09 座標校正複驗**：`python scripts/validate_gex.py --basis-compare` 以當日已知的 `台指期結算價 - 選擇權 F` 平移當日位階，用隔一交易日台指期主力月高、低、收驗證。共 **265 個配對交易日**(2025-08-04 ~ 2026-09-23)，排除 **14 個主力合約換月日**；價差中位 +57 點，範圍 −95 至 +527 點。原始履約價不改寫，舊回測仍可重跑。

| 同樣寬度的區間 | 隔日觸牆後收回 | 隔日收在區間內 |
|---|---:|---:|
| 原始選擇權履約價，未換算 | 54/157 = 34.4% | 162/265 = 61.1% |
| 當日基差換算成台指期估算點位 | 59/151 = 39.1% | 173/265 = 65.3% |
| 簡單基準：以當日台指期結算價為中心 | 53/136 = 39.0% | **182/265 = 68.7%** |

換算後比未換算好，但**未勝過只把同寬區間放在當日台指期價格中心**。兩者在隔日收盤是否落入區間的配對差異也不明確(McNemar exact p=0.163)。Signed Micro Flip 跌破後再下一天的絕對報酬中位 0.97%，維持在上方是 0.91%(p=0.133)；跌破後續跌 38.5%(n=52，方向 p=0.126)，沒有可確認的加速或方向優勢。這些是同一段歷史的描述，不是獨立樣本外績效；區間與 Flip 都依賴原本的 Dealer 方向假設。

以下保留先前**未換算座標**的 2026-08 驗證記錄，避免拿新結果覆蓋舊結果。

`scripts/validate_gex.py` 可重跑以下驗證。以下是 **278 個交易日**(2025-07-03 ~ 2026-08-21)跑出來的結果。所有對照組都是**把同一組位階隨機平移**後重算(保留寬度與不對稱比例),不是憑空比較。

| 測試 | 結果 | 判定 |
|---|---|---|
| **牆能當支撐壓力嗎**(碰到後退回牆內) | 實際 34.4% vs 隨機位階 34.1%,第 54 百分位 | ❌ 與隨機無異 |
| 觸及上牆後的穿透深度 | 中位數 **33% 牆距**、90 分位 **90%** | ❌ 真障礙不會這麼容易被穿過 |
| 隔日收盤落在牆內 | 63.7% vs 隨機 60.8%,第 93 百分位 | 🟡 弱,未達顯著 |
| **跌破 Micro Flip 會加速嗎** | 跌破組 0.85% vs 維持組 0.89%,p=0.202 | ❌ 不但沒加速,數字還略低 |
| **跌破後的方向** | 反彈 51% / 續跌 49%,p=1.000 | ❌ 完全隨機 |
| 負 gamma 是否預示大波動 | 隔日 \|報酬\| 中位 1.67% vs 0.88%,控制波動延續後三層中兩層顯著 | ✅ 統計上成立 |
| **↑ 但這個訊號有經濟價值嗎** | 見下方 | ❌ **沒有** |

**決定性測試 —— 訊號早就被 IV 定價了:**

| regime | 天數 | 當日 ATM IV 中位 | 實現/隱含比 |
|---|---|---|---|
| positive | 185 | 22.3% | 0.80 |
| negative | 45 | **38.1%** | 1.01 |

負 gamma 日的隱含波動率是正 gamma 日的 **1.7 倍**(p < 0.0001) —— 選擇權市場早就知道那些日子會震。扣掉 IV 已定價的部分後,GEX 對「實現減隱含」**沒有預測力**(p = 0.084;連續版本 Spearman rho = −0.058, p = 0.330)。

也就是說:「負 gamma → 隔日波動 2 倍」是**真的,但沒有用** —— 那些日子本來就是波動大的日子,而你付的權利金裡已經含了那份波動。

**所以這套東西實際能用的是什麼:**

- ✅ **gamma / OI 集中在哪裡** —— 這是不依賴 Dealer 多空假設的結構描述(Concentration Peak、Valley、剖面)，不等於可交易的支撐壓力
- ⚠️ 想知道「今天預期會不會震」,**直接看 ATM IV 就好**,不必繞一圈算 GEX
- ❌ 把牆當支撐壓力、把 flip 當觸發點 —— 資料完全不支持

**保留:** 樣本全部落在同一個大多頭(期間指數 +99%),空頭環境下結論未必相同;腳本共跑約十個檢定,**沒有做多重比較校正**,出現一兩個 p<0.05 屬預期內。判讀請以效果量與對照組分布為主,不要只看 p 值。

### ⚠ 靜態假設在台股不成立 — 哪些數字能信

GEX 的符號採靜態假設:**造市商 long call / short put**(`net = oi_c - oi_p`)。這個假設借自美股 SPX 的慣例 —— 散戶買 put 避險,造市商被迫 short put,於是形成負 gamma。

**用期交所的三大法人留倉實測(免費資料,`callsAndPutsDateDown`),2026-06-24 ~ 08-24 共 43 個交易日:**

| | 符合天數 | 平均淨額 | 與假設 |
|---|---|---|---|
| 自營商 CALL 淨買方 | 39/43(91%) | +4,201 口 | ✅ 相符 |
| 自營商 PUT **淨買方** | 41/43(95%) | +5,217 口 | ❌ **相反** |
| 兩者同時成立 | **2/43(5%)** | | |

原因是市場結構相反:台灣散戶大量**賣 put 收租**(2026-08-24 散戶端 put 空方 59% > 多方 54.5%),自營商接到的是 long put,不是 short put。

**所以哪些能信:**

| 輸出 | 依賴符號假設 | 狀態 |
|---|---|---|
| Concentration Peak / Valley、Call / Put Concentration、最強 Cluster | ❌ 分開使用 Call/Put `OI × |Gamma|` | ✅ 描述集中位置 |
| gamma×OI 剖面、`F`、基差 | ❌ | ✅ 有效 |
| Call Wall / Put Wall | ⚠️ 部分(現價上方 put OI 本來就少,下方 call OI 也少) | 🟡 大致可用,實測 8 天中 5-7 天與單邊定義同解 |
| Micro Flip、Macro Zero | ✅ 零軸穿越完全靠符號 | ❌ 不可信 |
| `regime` 正/負 Gamma 判定 | ✅ | ❌ 不可信 |

前端也分成兩區：**Gamma Concentration** 顯示純集中度位階；**Signed GEX Model**
顯示 Wall、Flip、Zero 與 Regime，並明標 Dealer 方向假設。

**不能只是把 put 的符號翻過來** —— 那會讓 `net` 等於 `gross`、永遠是正的,Micro Flip 直接不存在。真正的問題是我們對每個履約價套用同一個符號,但實際的長短分布因履約價而異。要修好需要**逐履約價的流量歸屬**(判斷每筆成交打在買價還賣價),那需要 tick 資料。

還有一層:期交所只分自營商/投信/外資三類,**沒有獨立的「造市者」欄位**。自營商混著登記造市者與方向性自營交易,且只持有全市場約 1/3 部位 —— 連「造市商是誰」在公開資料裡都不乾淨。

## 上榜天數與族群日增減

`data/momentum_members.csv.gz`(美股是 `us_momentum_members.csv.gz`)記錄每個交易日
通過動能篩選的**名單**, 欄位 `date, code, theme`。廣度只存檔數, 這份存的是「是誰」。

成本幾乎是零:`update_breadth()` 本來就逐日重跑過一次 `momentum_screen()` 才算得出
每天的檔數, 以前把名單丟掉、只留 `len()`, 現在順手留下來。也因為名單完全由歷史
價格決定, 第一次啟用時可以直接從 `history.csv.gz` 回補(台股回補出 81 個交易日)。

### 上榜天數

前端「動能篩選」與「族群題材」多一欄**上榜**, 第一天進榜標「新」。

連續按**交易日**算而不是日曆天 —— 中間隔週末或連假不算中斷, 但只要有一個交易日
掉出名單就歸零重數。滑過去會顯示起算日與有紀錄以來的累計天數(累計 > 連續, 代表
中間掉出去過又回來)。

### 族群的日增減

「族群題材」每組標題的檔數後面接一個 `+3` / `-2` / `±0`, 是**對前一個交易日**的
增減, 滑過去顯示前一日檔數。

前一天的個股用**最後一次看到的題材**歸類, 不是重跑一次當天的新聞。兩個理由:
昨天掉出名單的個股今天不會被標註, 沒有標籤可用; 而且要比的是「這個族群的檔數
變多還是變少」, 兩天用同一套標籤才比得準 —— 否則題材改名或人工覆寫會憑空生出
一組差值。今天有標註的以今天為準, 覆寫檔當第二順位。

**已知的偏差:** 剛啟用時回補的日子沒有題材(沒有當天的新聞可查), 昨天在榜、今天
掉出去又不在覆寫檔裡的個股只能算進「未歸類」, 所以「未歸類」的差值一開始會偏向
負值(實測台股 -6、美股 -10)。每天的題材現在都會寫回名單, 這個偏差會隨著紀錄
累積自行消失。

### --recompute

改了計算邏輯又還沒到下一個交易日時用:

```bash
python scripts/update_data.py --recompute
```

平常那條路在沒有新交易日時會直接跳過、不重新產出 latest.json, 所以新欄位要等到
隔天才看得到。這個旗標用現有歷史重算一次並寫檔, 不抓新資料。

## 美股族群題材

跟台股 `themes.py` 共用同一套引擎(抓 Google News、依「有幾則不同新聞提到」計分、
人工覆寫優先), 但**兩邊的分工剛好相反**, 因為關鍵字在美股幾乎不管用。

### 為什麼美股不能只靠關鍵字

把 2026-09-01 的 219 檔動能股標題做詞頻統計, 出現在最多檔的詞是:

```
stocktitan.net:176  earnings:142  gurufocus:101  simplywall.st:81
estimates:75  sells:72  quiver quantitative:68  insider:...  fair value:32
```

**前 70 名裡一個題材詞都沒有** —— gold、bitcoin、AI 全部排不進來。台股的標題
是題材密集的(CPO、磷化銦、散熱、軍工), 美股的 RSS 則被財經內容農場洗版。

實測純關鍵字只歸出 35%, 而且**成交值最大的名字幾乎全部落在未歸類**:SNDK、
CRM、PLTR、NOW、LITE、MRNA、HOOD、SHOP…。所以美股這邊:

* **`data/us_theme_overrides.csv`(人工/LLM 研究)是主力** —— 大型股靠它
* **關鍵字是補位** —— 抓那些新聞本來就很直白的中小型股(礦業、生技解盲)

合起來 **72% 檔數 / 98% 成交值**已歸類。前端在覆寫來源的個股名稱後面標一個 `●`。

### 兩個踩過的坑

**股票代號會撞到題材關鍵字。** Hudbay Minerals 的代號就是 `HBM`, 12 則標題全部
命中「記憶體 HBM」, 一檔銅礦公司被歸成記憶體股。比對前必須把代號從標題拿掉,
短代號(P、U、DC、AG、OR、IT、GO)尤其危險。

**媒體名也算內容。** Google News 標題結尾固定是「標題 - 媒體名」, AbCellera(生技)
被判成加密貨幣, 只因為其中幾則的來源叫 `CryptoRank`。

### RSS 摘要沒有用

原本想「不要只看標題」而去吃 RSS 的 `<description>`。實測 3066 則摘要, 平均 13.7
個詞, 其中**標題沒有的只有 1.0 個(7%)** —— 摘要基本上就是標題重複一次再接媒體名。
沒有新資訊, 反而讓媒體名多命中一次, 所以關掉了。要拿到標題以外的東西只能抓文章
本文, 那正是覆寫檔那條路在做的事。

### 2026-08 這波的實際題材

## 排程:為什麼不能只靠 GitHub

**GitHub 的 `schedule` 不會照你寫的時間跑,而且會整班丟掉。** 這不是故障,是它對公開
repo 的 best-effort 設計 —— 高負載時直接不執行,官方文件也這麼寫。

實測本 repo 2026-07-21 ~ 08-31 共 30 個交易日的 schedule 觸發紀錄:

| 期間 | 設定班數 | 實際執行 |
|---|---|---|
| 07-21 ~ 08-18 | 1 班 | 每天 1 班 |
| 08-19 ~ 08-26 | **2 班** | 每天 1 班 |
| 08-27 | 2 班 | 2 班(唯一一次) |
| 08-28 | 2 班 | 1 班 |
| 08-31 | **3 班** | **0 班** |

開跑時間從 04:07 到 23:13 都出現過,跟 cron 寫的幾點幾乎無關;誤點中位數 48 分、
最長 175 分。重點是**多排班數並不會增加當天跑到的機會** —— 它一天大概只放一班,
加班次只是換一張同樣的樂透彩券,而 08-31 那天連一張都沒中。

所以 cron 保留著當免費的備援,真正的觸發來源放在外部。

### 設定外部觸發

需要一組 GitHub token,**請自己產、自己貼,不要貼進任何對話或檔案裡**。

1. GitHub → Settings → Developer settings → **Fine-grained personal access tokens** → Generate new token
   - Repository access:**Only select repositories** → `tw-momentum`
   - Permissions → Repository permissions → **Actions: Read and write**
   - 到期日建議設一年,到期要記得換
2. 到 [cron-job.org](https://cron-job.org)(免費)建立 Cronjob:
   - URL:`https://api.github.com/repos/wesley314789/tw-momentum/actions/workflows/daily.yml/dispatches`
   - Schedule:時區選 **Asia/Taipei**,週一至週五 **15:35** 和 **19:00** 各建一個
   - Advanced → Request method:**POST**
   - Headers:
     - `Accept: application/vnd.github+json`
     - `X-GitHub-Api-Version: 2022-11-28`
     - `Authorization: Bearer <你的 token>`
   - Body:`{"ref":"main"}`
3. 成功的回應是 **HTTP 204 No Content**(沒有 body,這是正常的)。401 = token 錯,
   403 = 權限沒給 Actions write,404 = repo 或 workflow 檔名不對。

先用一行 curl 驗證再去設服務。**注意引號寫法跟 shell 有關** —— 用錯會拿到
`400 Problems parsing JSON`(但那其實代表 token 是好的:認證過了才會進到解析 body
這一步,順帶看回應標頭的 `X-RateLimit-Limit`,5000 是已認證、60 是沒認證)。

bash / Git Bash / Linux:

```bash
curl -i -X POST -H "Accept: application/vnd.github+json" -H "X-GitHub-Api-Version: 2022-11-28" -H "Authorization: Bearer YOUR_TOKEN" https://api.github.com/repos/wesley314789/tw-momentum/actions/workflows/daily.yml/dispatches -d '{"ref":"main"}'
```

cmd.exe —— 不認單引號,雙引號要用反斜線跳脫:

```bat
curl -i -X POST -H "Accept: application/vnd.github+json" -H "X-GitHub-Api-Version: 2022-11-28" -H "Authorization: Bearer YOUR_TOKEN" https://api.github.com/repos/wesley314789/tw-momentum/actions/workflows/daily.yml/dispatches -d "{\"ref\":\"main\"}"
```

PowerShell —— 同上,而且開頭必須寫 `curl.exe`,否則會被 `Invoke-WebRequest` 的別名接走。

**重複觸發是安全的。** `daily_update()` 是掃區間補洞,沒缺口就什麼都不寫;GEX 和
美股那兩支也是冪等的。外部服務和 GitHub 自己的 cron 同一天都跑到,只是誰先誰後,
不會寫壞資料,也不會產生重複的 commit(沒變更就直接 exit 0)。
